# PairFit · 多步骤流程与导航规范

> 版本:v1.0 · 2026-09-14 · 维护方:Coding Agent(随 BUG-FIX-2 落地)
>
> 本文档定义 **所有多步骤流程** 的统一交互规则。任何 PF 涉及多步骤 / 多步向导 / 多步输入时,必须按此实现;UI 设计 Agent 评审时也以本文档为依据。

## 2. 强制规则

任何多步骤流程 **必须** 满足以下 5 条:

### 2.1 每步有「上一步」

- **步骤 0(第一步)**:显示「← 返回」按钮 → 触发 **取消流程**(二次确认)
- **步骤 N(N≥2)**:显示「← 上一步」按钮 → 回到步骤 N-1,保留已填数据
- **最后一步**:不再显示「下一步」,只显示「完成 / 锁定 / 确认」按钮
- 按钮位置:页脚左侧(`ghost` 变体,左侧图标 + 文字),与右侧主 CTA 对齐

### 2.2 任何一步可以「取消」

- **取消入口**(必须全部提供,任意一个即可触发):
  1. **顶部 X 按钮**:固定在 `PageHeader` 的 `trailing` 位置,圆形 36×36,`<X>` 图标
  2. **第一步的「← 返回」按钮**(同上,语义统一)
  3. **键盘 Esc** —— 即便用户没看到 X 按钮也能退出
- **取消流程**:弹出 **二次确认 Modal**,文案:
  - 标题:`Leave {流程名}?` / `要退出 {流程名} 吗?`
  - 正文:说明当前进度会被丢弃,以及如何重新进入
  - 操作:「Keep editing / 继续填」(ghost)+「Discard & leave / 放弃并离开」(danger)
- **取消目标路径**:
  - 有可见「入口页」的流程(注册流、修改目标):跳回 **入口页**
  - 无明确入口的:跳回 **Tab 首页** 或流程发起方
  - 约定:Onboarding 的取消目标 = `/me`(已登录)/ `/`(未登录)

### 2.3 步骤状态保留

- 所有输入值存在 **组件本地 state**,不依赖外部 store
- 「上一步」**不重置** 已填字段
- 离开 / 取消 / 完成 → 卸载组件时清空 state(无需手动)
- 例外:Onboarding 的第 2 → 3 步会在 step 2 提交时持久化草稿到 `goalStore`(用于预览图表),这是预期行为,不是数据丢失

### 2.4 键盘快捷键

| 键 | 行为 | 备注 |
|---|---|---|
| `Esc` | 取消 / 关闭确认 Modal | 任何步骤 / 确认态都可触发 |
| `←` | 上一步 | 仅当焦点不在 `<input>` / `<textarea>` |
| `→` | 下一步(若可前进) | 同上 |

实现要点:
- 用全局 `keydown` 监听 + `useEffect` 注册 / 卸载
- 检测 `e.target.tagName === 'INPUT' \|\| 'TEXTAREA' \|\| isContentEditable` 时跳过箭头键
- `Esc` 永远响应(包括确认 Modal 内)
- 焦点陷阱:Modal 打开时把焦点送到「继续填」按钮上(防止 Tab 跑到背景)

### 2.5 进度指示器

- 顶部显示「第 N / M 步」+ 百分比
- 进度条(`<ProgressBar>`)颜色用 `brand → accent` 渐变
- 最后一步(庆祝 / 完成态)**不显示**进度条

## 3. 不要做

- ❌ 不要把「上一步」做成「撤销当前步」(语义混淆)
- ❌ 不要在「上一步」时清空已填数据(用户会炸毛)
- ❌ 不要让「下一步」在不可前进时还显示(要么禁用,要么切换文案为「完成」)
- ❌ 不要在 Modal 里默认勾选「不再提醒」(见 `interaction-spec.md § 3.7`)
- ❌ 不要用 `window.confirm()` / `alert()`(破坏沉浸感,i18n 不可控)

## 4. 复用 / 抽象策略

| 阶段 | 处理 |
|---|---|
| **第一次出现**(Onboarding) | 就近放在 `pages/Onboarding.tsx` 的 `ExitConfirmDialog` 中,作为局部组件 |
| **第二次出现**(PF-4 / PF-5 / PF-6 任一) | **必须**抽到 `components/ui/ConfirmDialog.tsx`,作为通用组件 |
| **第三次及以后** | 在通用组件上加 `variant` / `tone` 等参数,不要复制粘贴 |

`ExitConfirmDialog` 抽到通用组件时,签名建议:

```ts
interface ConfirmDialogProps {
  open: boolean;
  title: string;
  body?: string;
  cancelLabel: string;
  confirmLabel: string;
  confirmTone?: 'danger' | 'primary';
  onCancel: () => void;
  onConfirm: () => void;
}
```

## 5. 验收清单(每个新流程落地前自查)

- [ ] 顶部 X 按钮存在且 `aria-label` 正确
- [ ] 第一步有「← 返回」按钮,触发取消流程
- [ ] 中间步骤有「← 上一步」按钮,保留已填数据
- [ ] 最后一步只有「完成」按钮,没有「下一步」
- [ ] 任何步骤按 Esc 弹出确认 Modal
- [ ] 确认 Modal 内按 Esc 关闭,不离开
- [ ] 确认 Modal 的「放弃」按钮用 `danger` 变体
- [ ] 取消后跳到正确的入口页
- [ ] 进度条在中间步骤正确显示百分比
- [ ] 焦点不在 input 时,← / → 能切换步骤

---

## 6. 已知 / 显式遗留

- 当前 `ExitConfirmDialog` **没有焦点陷阱**(focus trap)——只在 Onboarding 全屏页面里使用,问题不大;抽出通用组件时必须补上
- 没有 portal —— 同上原因,全屏场景下 z-index `50` 已足够
- 取消 / 上一步的过渡动效沿用 `animate-slide-up`(0.25s),没做反向动画(成本 / 收益不成正比)
