# PairFit · 情侣双向健身 App(MVP PRD)

> **版本**:v1.0 final · 立项日期:2026-09-14 · PM:B2C 产品经理(共创)
> **状态**:Round 4 已签字(2026-09-14),M1 开发中

## 1. 背景与目标

### 1.1 一句话定位
**PairFit** 是海外发布的 C 端健身 App,**主打"情侣 1v1 协作健身 + 双向目标 + 虚拟币奖惩 + 语音优先输入"**,不框死单人用户。

### 1.2 要验证的产品假设
- **H1(假设)**:在海外 25-35 岁年轻情侣中,存在"双向健身目标(一人减肥一人增重) + 互相激励"这一未被现有 App(MyFitnessPal / Lose It / Strava / Finch)充分满足的细分需求。
- **H2**:语音输入 + AI 食物估算可显著降低健身记录成本(目标:输入时长从 60 秒打字降到 10 秒说话)。
- **H3**:"情侣订阅 1 人付费 = 2 人解锁"模型比"双人各付"更利于留存(目标:订阅 D30 留存 > 60%)。

### 1.3 MVP 范围(这版要交付的)
- Web 单页(浏览器可玩)
- 单人记录 + 情侣绑定协作(两模式并存)
- 三大记录:体重 / 饮食 / 运动
- 语音输入(微信长按说话式)+ AI 食物估算(粗估 ±25%)
- 虚拟币(Coins)奖惩 + 双方确认制
- 体重曲线 + 饮食卡路里 + 运动时长 三张趋势图
- 免费基础 + 订阅解锁(情侣 1 人付费 = 2 人解锁,V1.1 再做支付)
- 英文为主 + 中文二档

### 1.4 Out of scope(明确不做)
- ❌ 真实支付(V1.1,等海外银行卡激活)
- ❌ 云同步(V1.1,本期全 localStorage)
- ❌ 大团体 / 群组(V2,MVP 仅 1v1)
- ❌ AI 智能推荐教练 / 健身计划(V2)
- ❌ iOS / Android 原生 App(V1.1,本期只 Web)
- ❌ Apple Watch / 智能手环接入(V2)

## 2. 用户画像与典型场景

### 2.1 画像 A:**异地恋情侣(英文用户)** ⭐ 主目标
- **基础属性**:25-35 岁,白领,欧美/澳洲,英文为母语
- **时间地点情绪**:工作日午休、晚上 8-10 点、周末早上,异地/同住皆有,情绪偏积极
- **现有替代**:MyFitnessPal(单机,无社交)、Strava(社交,但只有运动)、Couple Game(恋爱 App,无健身)
- **痛点强度**:🌟🌟🌟🌟🌟 — 异地时没人监督、记录容易忘、看不到 ta 的进度
- **典型场景**:"我今天下班练了 30 分钟椭圆机 + 吃了沙拉,你呢?"

### 2.2 画像 B:**同住情侣(中文用户)**
- **基础属性**:25-32 岁,海外华人 / 中国一二线,中文为主
- **时间地点情绪**:晚上 7-11 点在家、周末白天,情绪随吵架波动
- **现有替代**:Keep(单机)、薄荷健康(单机)
- **痛点强度**:🌟🌟🌟🌟 — 俩人目标相反(减肥 + 增重),找不到一起用的 App
- **典型场景**:"你今天又吃炸鸡了?说好的一起减肥呢?"

### 2.3 画像 C:**海外华人单身用户**
- **基础属性**:25-40 岁,留学生 / 华人白领,英文+中文双语
- **痛点强度**:🌟🌟🌟 — 不需要社交,只要"轻量记录工具"
- **典型场景**:用户只想自己用,不想绑情侣 — **必须允许不绑定**

## 5. 用户故事与验收标准

### 5.1 给定-当-则 格式(覆盖 12 个核心故事)

**US-01 首次注册**
- **给定**:新用户打开 PairFit
- **当**:输入邮箱 + 密码(≥8 位)+ 昵称,点注册
- **则**:跳到"目标设定"页,引导设目标

**US-02 设定健身目标**
- **给定**:已注册用户首次进入
- **当**:选择方向(减肥 / 增重)+ 输入起始体重 + 目标体重 + 期望节奏(每周 -0.5kg / +0.3kg)
- **则**:生成"目标曲线",显示预计达成日期

**US-03 体重记录(数字)**
- **给定**:已设目标用户
- **当**:进入"体重"页,输入数字(支持 kg/lb 切换),点保存
- **则**:写入今日记录,曲线新增一点

**US-04 体重记录(语音)**
- **给定**:已设目标用户
- **当**:长按麦克风按钮,说"今天 65.5 公斤"
- **则**:松开后识别数字 → 自动填入 → 点保存即可;失败显示"没听清,再说一次"

**US-05 饮食记录(语音)**
- **给定**:已设目标用户
- **当**:长按麦克风,说"中午吃了鸡腿饭和一杯奶茶"
- **则**:调用 AI 估算 → 显示"~800 kcal · 鸡腿饭 550 + 奶茶 250"+ 用户确认 → 写入

**US-06 运动记录(语音)**
- **给定**:已设目标用户
- **当**:长按麦克风,说"跑步 30 分钟"
- **则**:识别 → 显示"跑步 30min · 估算 300 kcal" → 确认 → 写入

**US-07 情侣绑定(生成邀请码)**
- **给定**:已设目标用户
- **当**:进入"情侣"页,点"生成邀请码"
- **则**:6 位字母数字(例 A2K9P7),可分享,24h 过期

**US-08 情侣绑定(输入邀请码)**
- **给定**:用户有 ta 的邀请码
- **当**:进入"情侣"页,输入 6 位码
- **则**:对方收到绑定请求 → 同意后绑定成功,显示"已和 XX 绑定"

**US-09 双人协作(看 ta 的进度)**
- **给定**:已绑定的情侣
- **当**:进入首页 / 情侣页
- **则**:看到 ta 今日的体重 / 饮食 / 运动卡片 + 鼓励按钮

**US-10 虚拟币奖惩**
- **给定**:已绑定 + 用户达成 / 失败今日目标
- **当**:系统判定达成 / 失败
- **则**:通知对方 → 对方确认 → Coins 增加 / 扣减 → 双方都能看到 Coin 变化

**US-11 趋势总览**
- **给定**:已记录 ≥7 天数据
- **当**:进入"趋势"页
- **则**:看到体重 / 卡路里 / 运动三张 7/30/90 天切换曲线

**US-12 订阅占位(纯展示,本期不触发解锁)**
- **给定**:已绑定情侣
- **当**:用户进入订阅页(P8)
- **则**:看到 Pro 解锁功能列表(无广告 + 高级曲线 + 自定义主题 + AI 周报 + 云同步)+ 价格表($4.99/月 或 $29.99/年,1 人付费 = 2 人共享);点订阅按钮 → 弹"暂未开放,等 V1.1 海外支付上线"。**本期不实现解锁触发**,验证逻辑写进代码但不激活。7 天解绑冷却防滥用仍生效。

### 5.2 关键故事附埋点

| 故事 | 埋点事件 | 参数 |
|---|---|---|
| US-01 | `register_success` | source, locale |
| US-04 / 05 / 06 | `voice_input_attempt` / `voice_input_success` | type, duration_ms, success |
| US-05 | `ai_food_estimate` | calories, confidence |
| US-07 / 08 | `pair_invite_create` / `pair_invite_accept` | invite_code |
| US-09 | `view_partner_today` | partner_id |
| US-10 | `coin_earn` / `coin_deduct` | reason, amount |
| US-12 | `subscribe_activate` / `pair_unlock` | pair_id |

## 6. 核心流程与页面(页面 / 元素 / 交互 / 异常态)

### 6.1 主导航(Tab Bar,底部 5 个)
1. **首页** — 今日打卡 + 目标进度
2. **记录** — 体重 / 饮食 / 运动 三选一
3. **情侣** — ta 的进度 + 邀请码 + 关系状态
4. **趋势** — 三张曲线
5. **我的** — 订阅 / 设置 / 帮助

### 6.2 关键页面清单(8 个核心页)

| 页面 | 关键元素 | 交互 | 异常态 |
|---|---|---|---|
| **P1 注册/登录** | 邮箱输入 / 密码 / 昵称 / 登录切换 Tab | 提交 → loading → 跳转 | 邮箱已注册 → 提示 |
| **P2 目标设定** | 方向单选 / 起始体重 / 目标体重 / 节奏 slider | 完成 → 生成曲线预览 | 输入非法 → 校验 |
| **P3 今日打卡(首页)** | 三模块卡片(体重/饮食/运动)+ 进度条 + 一键语音按钮 | 点模块 → 跳对应录入 | 未记录 → 空状态 |
| **P4 体重录入** | 数字输入 / 单位切换 / 语音按钮 / 历史曲线缩略 | 保存 → 弹成功动画 | 语音失败 → 重录 |
| **P5 饮食录入** | 语音按钮 / AI 估算显示 / 营养素条 / 确认按钮 | 估算 → 确认 → 保存 | 估算不准 → 手动改 |
| **P6 情侣页** | 邀请码 / 绑定状态 / ta 今日 / 鼓励按钮 / 解绑 | 邀请 → 分享 sheet | 已绑定 → 显示对方 |
| **P7 趋势页** | 三张曲线 + 7/30/90 切换 + AI 周报卡 | 切换时间窗 | 数据不足 → 提示 |
| **P8 我的** | 订阅卡片(纯展示) / 单位 / 语言 / 导出 / 清空 | 点订阅 → "暂未开放" 提示 | 解绑 → 7 天冷却 |

### 6.3 异常态全局规则
- **网络断**(MVP 无网络,但离线检测):所有数据写 localStorage,网络恢复不主动同步
- **语音识别失败**:Toast "没听清,再说一次",重试按钮
- **AI 估算超时**(>10s):降级为"模糊估算",给个区间 600-1000 kcal,让用户填实际值
- **绑定码过期 / 错误**:Toast "邀请码无效或过期",重新生成
- **未绑定用户访问情侣页**:空状态 + "生成邀请码" CTA

## 7. Onboarding 与首次体验

### 30 秒 / 1 分钟 / 5 分钟 啊哈时刻

- **0-30 秒**:注册 → 进入"目标设定"(视觉:目标曲线动效出现)
- **30-60 秒**:录第一条体重 / 饮食(语音 1 次完成)
- **1-5 分钟**:看到第一张"今日打卡进度"卡片
- **5 分钟(绑定后)**:**啊哈时刻** = 收到 ta 的"鼓励"表情 + Coin 收入弹窗

**首次流程硬要求**:
- 全程不超过 3 步操作到第一次记录完成
- 引导性文案 0 行业黑话("卡路里" 可以,"TDEE" 不行)
- 第一条记录成功 → 弹庆祝动效 + "你已超越 80% 的首次用户"

## 8. 增长与留存策略(AARRR)

### 8.1 Acquisition(拉新)
- **Product Hunt 发布**(上线后 2 周)
- **Reddit**:r/fitness、r/loseit、r/bodyweightfitness 发"我和女朋友的健身 App"故事
- **TikTok / Reels**:情侣 Vlog 拍摄 30 天挑战,植入 App
- **ASO**:keywords = "couple fitness", "weight loss together", "voice food tracker"

### 8.2 Activation(激活)
- 注册 → 首次记录转化率 > 70%
- 引导页强化"30 秒设定目标 + 10 秒语音记录"

### 8.3 Retention(留存)
- **D1 留存 > 40%**(看到 ta 的鼓励是关键)
- **D7 留存 > 25%**
- **D30 留存 > 15%**

### 8.4 Revenue(变现)
- 免费基础 + Pro 订阅 $4.99/月 或 $29.99/年
- 情侣订阅 **1 人付费 = 2 人解锁**(不溢价)

### 8.5 Referral(裂变)
- 绑定机制本身 = 拉新(每个新用户都拉 ta 的另一半)
- **隐含 K 因子 = 1.0**(理论上一对情侣 = 2 个用户)

## 9. 增长实验(假设 / 指标 / 最小样本量 / 灰度比例 / 决策规则)

| 实验 ID | 假设 | 指标 | 最小样本 | 灰度比例 | 决策规则 |
|---|---|---|---|---|---|
| **E-01 语音 vs 文字** | 语音输入记录成功率 > 文字 | 记录完成率 | 200 / 组 | 50% 灰度 | 语音组 ≥ +10% → 全量 |

## 10. 非功能性需求

| 类别 | 要求 |
|---|---|
| **性能** | 首屏 < 2s,语音识别响应 < 3s,AI 估算 < 10s,页面切换 < 300ms |
| **弱网** | MVP 全本地,不依赖网络;V1.1 加离线缓存 |

| **多语言** | 英文 / 中文双语,语言切换实时生效 |
| **单位** | kg / lb 切换(影响输入和曲线显示) |
| **数据导出** | 一键导出 JSON,包含所有记录 + 关系 + Coins |
| **数据清除** | 设置页"清空所有数据"按钮,二次确认 |
